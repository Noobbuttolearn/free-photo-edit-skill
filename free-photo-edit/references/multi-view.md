# 三视图与多机位

用户要求同一主体的多个方向时读取本页；普通单图编辑不增加这些步骤。本页用于规划、机位控制和验收，不替代原台账、生成额度、白边或原图保护规则。

## 先确定“视图”的含义

- 产品正侧背：相机、比例和背景固定，旋转同一产品；通常用于外观展示。
- 同场景多机位：家具保持世界位置和朝向，移动相机；背景应随相机改变，不能为了保留原场景正立面而牺牲主体正面。
- 工程正投影：尺寸、投影和结构需可靠的CAD、3D或充分实拍依据。单张照片推演的外观图不能标为经测量验证的工程三视图。

沿用客户已确认的类型、张数和参考关系，不重复询问。尚有实质歧义时只问会改变拍摄方式的那一项。

## 一组共用一个主体合同

在生成前为整组保存共同事实，由客户在方案里核对：

1. 主体类别、场景中这一类主体的明确总数。数不清时先确认，不用“保持数量”代替整数，也不把示例数量变成默认。
2. 唯一目标实例：位置描述、编号，以及在原场景副本上的框选或裁切参考。不能正面拍左边椅子、侧面换右边同款，再声称同一主体的机位变化。
3. 外形、材质、纹理和结构等身份特征；场景的地标与家具位置关系。
4. 主体正面定义、侧面选择、正侧背各自必须看到的外观证据。机位角度以主体为参照，不以厨房、墙或原照片方向为参照。
5. 是否允许先调整主体位置，调整后是否冻结这一摆放。比如椅子坐人侧被餐桌挡住时，可以提出先拉出椅子的摆拍方案；必须明说并确认，不能靠新增一把前景椅子解决。
6. 不可见结构/空间的处理：允许合理推演，还是缺少参考必须补拍。推演不构成真实产品结构保证。

数量指物理场景中的实例，不要求每张都露出全部实例。核查空间关系和自然遮挡；看见3把并不能单凭可见数量断言原来4把中的一把已被删除，反过来也不能假定缺失物体都被遮住了。无法判断时保留为待核对，避免硬判通过。

## 用机位示意减少文字歧义

可本地绘制目标框选、正面朝向箭头及0°/90°/180°观察位置，不消耗生图次数。示意要明确它是方向说明，而非测量得到的房间平面图或产品3D模型。让客户看到框选目标和相机关系，再批准整批。

正面要见主体正面特征；椅子例子是座面与靠背内侧。侧面应接近约定的90°，不要用斜前/斜后视图冒充。背面显示主体背面；椅子例子是靠背外侧。并非所有主体都适用“坐人侧”，按实际物体定义。

参考图分工写清楚：身份参考提供外观，原场景提供物理布局，机位示意提供方向，已验收首图提供同组身份和摆放锚点。示意图上的文字、框线和箭头不得进入最终照片。

对新机位重建，如果把原场景照片作为第一张编辑底图容易继承原相机，可以改用按约定内容尺寸本地创建的中性空画布作为生成目标，将原场景作为参考；仅启用白边时由prepare在调用前添加白边。此方法适用于允许重建的visual模式，不得用于声称区域外像素不变的局部编辑。不要把空画布、示意图或反复重画本身算作已生成的场景成品。

## 先校准，再展开

对方向容易混淆或尚未验证的多视图方案，优先在同一已批准额度内先生成最关键的1张（通常正面）。多个模型分别校准，不能拿A模型通过代替B模型通过。

- 首图提交前正常prepare/reserve；未提交的后续机位不提前预留或扣次数。
- 首图返回后核对目标实例、机位、数量与遮挡、外观、场景、主体边界和白边；白边通过不等于画面通过，模型自己口述“符合”也不是验收证据。
- 首图通过后，后续机位沿用同一个合同，并可携带同模型已验收首图作为身份/摆放参考。新机位仍按自身方向执行，不能复制首图相机。
- 首图失败或不合格时，先停止该模型尚未提交的机位，说明缺项。不能自动重试、换模型补出、改角度再抽，或把最多3张变成3张以外另加试拍。
- 在明确授权并已有可靠方案的任务中可按需并行；阶段校准是降低重复失败的推荐，不改变客户已授权的数量和流程。

## 同组验收

逐张实际看图，并对整组比较：同一目标实例及身份是否保持；角度是否有真实区别；数量/遮挡是否自洽；背景变化是否对应相机运动；家具是否被暗中挪动；图案、材质和结构比例是否漂移。记录具体未通过原因，不用文件名、模型名称或一张画布校验结果代替检查。

只有合格图片进入原deliver流程。失败、不确定或缺少关键参考的图保留为候选/待核对，不标为完成三视图。没有实际新生图验证时，只能说明方案和离线机制已更新，不能宣称模型成图成功率已经提高。

## 与现有脚本配合

原 `photo_edit.py` 的plan格式与CLI保持兼容；它管理数量与交付，不自动理解相机语义。宿主把共同主体合同、机位图和验收记录保存在任务目录，与台账关联。每个variant的requirement写该机位的实际关系；用正常prepare携带身份、场景、示意和可用锚点参考，第一张仍是已确认内容尺寸的编辑目标。不要把合同JSON当图片输入。
